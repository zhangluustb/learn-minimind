# 09 - LLM 工程实践面试 30 题

## 1-10：系统架构

1. 在线推理系统的核心模块有哪些？
- 答：网关、调度器、模型服务、缓存层、观测与告警。

2. 为什么要做 OpenAI API 兼容层？
- 答：降低客户端改造成本，快速接入生态工具。

3. 单机多卡与多机多卡如何选？
- 答：先单机多卡控复杂度，容量/吞吐不足再扩多机。

4. 推理服务中“吞吐”和“延迟”如何平衡？
- 答：通过动态 batching、优先级队列和 SLA 分层。

5. 什么时候需要模型路由（model routing）？
- 答：按任务难度/成本把请求分配到不同规格模型。

6. 什么是降级策略？
- 答：高峰期切短上下文、降低 max_tokens、回退小模型。

7. 为什么要做请求幂等？
- 答：重试场景避免重复扣费和重复副作用。

8. 配额与限流怎么设计？
- 答：按用户/租户维度设置 QPS、并发、tokens/day。

9. 多租户隔离如何做？
- 答：鉴权隔离、资源配额隔离、日志与数据隔离。

10. 为什么要区分同步和异步接口？
- 答：长文本生成适合异步任务队列，降低网关阻塞。

## 11-20：性能与成本

11. 推理成本主要由什么决定？
- 答：模型规模、上下文长度、输出长度、硬件单价与利用率。

12. Prefill 与 Decode 哪个更贵？
- 答：长上下文场景 prefill 重，长输出场景 decode 累积更重。

13. continuous batching 的价值？
- 答：让不同时间到达请求共享 batch，提高 GPU 利用率。

14. 为什么要做 prompt cache？
- 答：复用相同前缀的 prefill 结果，显著降时延与成本。

15. KV-Cache 碎片化怎么处理？
- 答：分页管理（paged attention）和内存回收策略。

16. 量化上线前要验证什么？
- 答：关键任务质量回归、稳定性、峰值延迟与吞吐。

17. 什么时候需要 speculative decoding？
- 答：低 batch、高时延敏感场景，尤其大模型单请求。

18. 为什么观测 p95/p99 延迟比平均值更重要？
- 答：用户体验由尾延迟决定，SLA 也通常按尾延迟约束。

19. 如何识别 GPU 空转问题？
- 答：结合利用率曲线和队列深度，查看是否被 CPU/I/O 阻塞。

20. 成本优化优先级建议？
- 答：先利用率（batch/调度），再量化，再模型路由。

## 21-30：可靠性与安全

21. 如何防止 prompt injection？
- 答：系统提示隔离、工具白名单、输出策略校验。

22. 工具调用安全边界怎么划？
- 答：最小权限、参数校验、执行沙箱、审计日志。

23. 为什么要做输出审核？
- 答：拦截有害内容、隐私泄露和政策违规回答。

24. 线上回滚策略怎么做？
- 答：灰度发布+版本标识+一键回滚+会话兼容处理。

25. 模型升级如何避免“静默退化”？
- 答：离线回归集 + 在线 A/B + 指标阈值自动熔断。

26. 日志中哪些字段必须记录？
- 答：请求 ID、模型版本、tokens、延迟、错误码、过滤标签。

27. 如何处理超时请求？
- 答：可中断生成、部分结果返回、异步续跑和重试策略。

28. 为什么要做可解释错误码？
- 答：便于客户端重试与排障，减少支持成本。

29. 数据合规在 LLM 服务中关注什么？
- 答：PII 保护、数据保留期限、跨境与审计要求。

30. 一句话总结 LLM 工程实践？
- 答：本质是“质量、时延、成本、安全”的持续多目标优化。

## 面试加分回答模板

- 先说架构分层。
- 再给关键指标（QPS、p95、tokens/s、成本/千 token）。
- 最后讲一次真实故障与回滚复盘。
