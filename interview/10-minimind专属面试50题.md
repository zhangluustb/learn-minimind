# 10 - minimind 专属面试 50 题

## 说明

- 本题库聚焦 minimind 项目本身，适合“项目深挖型”面试。
- 建议每题回答结构：结论 -> 项目实现 -> 数据/效果。

## 1-10：项目定位与总体设计

1. minimind 的核心价值是什么？
- 答：用低成本、短周期复现 LLM 全流程，强调教学与可实践性。

2. 为什么选择 64M 参数级别？
- 答：单机可跑通、迭代快，便于理解端到端流程。

3. minimind 覆盖了哪些训练阶段？
- 答：预训练、SFT、LoRA、RLHF/RLAIF、蒸馏。

4. minimind 与工业大模型项目的关系？
- 答：是“机制缩小版”，流程一致、规模不同。

5. 项目技术栈为什么选 PyTorch？
- 答：研究生态成熟、可读性高、便于教学扩展。

6. 你如何向非技术同学解释 minimind？
- 答：用几元成本体验“从零训出会聊天模型”的完整流水线。

7. 该项目最适合哪类学习者？
- 答：想系统理解 LLM 训练与部署的工程师和学生。

8. 项目最大的工程挑战是什么？
- 答：在资源受限下平衡训练稳定性、速度与效果。

9. 你做过哪些改造？
- 答：可答数据清洗、训练参数、评估脚本、部署接口等具体项。

10. 项目成功的衡量标准？
- 答：能稳定复现训练流程，且关键任务质量可感知提升。

## 11-20：模型结构与实现细节

11. minimind 的 Attention 为什么采用 GQA？
- 答：减少 KV-Cache 占用，推理更省显存。

12. n_heads 与 n_kv_heads 如何影响性能？
- 答：KV 头越少缓存越省，但可能有少量质量损失。

13. 为什么使用 RoPE？
- 答：相对位置建模自然，长文本外推更友好。

14. 项目中的 RMSNorm 有何收益？
- 答：训练更稳、速度更快，工程实现简洁。

15. FFN 为什么采用 SwiGLU？
- 答：门控非线性更强，通常比普通 GELU FFN 效果更好。

16. 是否支持 MoE？
- 答：可通过模块化前馈替换实现稀疏专家路径。

17. MiniMindBlock 的典型数据流？
- 答：PreNorm -> Attention -> Residual -> PreNorm -> FFN -> Residual。

18. 权重共享（embedding tying）有做吗？
- 答：若启用可减参数并提升泛化，一般建议使用。

19. QK-Norm 在该项目里的意义？
- 答：控制 attention logits 尺度，提升训练稳定性。

20. 该架构有哪些可扩展点？
- 答：长上下文策略、MoE、量化、并行与工具调用。

## 21-30：训练管线与调参

21. 预训练数据格式如何组织？
- 答：文本 token 化后按序列切片，构造 next-token 监督。

22. 预训练 loss 怎么算？
- 答：shifted labels 的 cross-entropy。

23. SFT 与预训练关键差异？
- 答：SFT 使用对话模板和 loss mask，仅训练 assistant 回答区间。

24. chat template 为什么关键？
- 答：决定模型对角色和轮次边界的理解。

25. LoRA 在 minimind 中怎么接入？
- 答：在线性层注入低秩增量，仅训练 LoRA 参数。

26. LoRA 的主要超参有哪些？
- 答：rank r、alpha、dropout、target modules。

27. DPO 在项目中起什么作用？
- 答：用偏好对直接优化策略，减少 RM+PPO 复杂度。

28. RLAIF 相比 RLHF 的优势？
- 答：降低人工标注成本，迭代速度更快。

29. 你如何定位训练不收敛问题？
- 答：先看 LR/warmup、梯度范数、数据质量、mask 逻辑。

30. checkpoint 应保存哪些状态？
- 答：模型、优化器、scheduler、global step、AMP scaler、RNG states（Python/NumPy/PyTorch/CUDA）以及 dataloader/sampler 进度，用于可复现恢复。

## 31-40：推理与部署

31. KV-Cache 在 minimind 推理中的作用？
- 答：避免重复计算历史 token，显著提速。

32. 为什么要支持流式输出？
- 答：改善用户感知延迟，提升交互体验。

33. 如何兼容 OpenAI API？
- 答：提供 /v1/chat/completions 兼容接口与消息格式。

34. 本地部署如何做轻量化？
- 答：量化（INT8/INT4）+ CPU/GPU 混合策略。

35. llama.cpp 路线适用于什么场景？
- 答：边缘端/CPU 场景，追求低资源部署。

36. vLLM 路线适用于什么场景？
- 答：高并发服务场景，依靠高效调度提升吞吐。

37. 如何设置最大上下文和输出长度？
- 答：按显存预算和 SLA，做动态上限控制。

38. 线上如何做版本切换？
- 答：灰度发布，按流量比例逐步放量并监控回归。

39. 推理质量回归集怎么构建？
- 答：覆盖通用问答、指令遵循、安全拒答、专业任务。

40. 成本优化最有效动作是什么？
- 答：先提高利用率（批处理/调度），再量化和模型路由。

## 41-50：项目深挖与面试实战

41. 你在 minimind 中最有代表性的改进是什么？
- 答：给出一个可量化例子（如训练提速、评估提升、部署降本）。

42. 如何证明改进有效而非偶然？
- 答：固定随机种子、对照组、重复实验、显著性统计。

43. 项目里最大的坑是什么？
- 答：可答数据质量、模板错误、mask bug、OOM 调参等。

44. 你是如何排查这个坑的？
- 答：最小复现 -> 指标监控 -> 定位 -> 回归测试。

45. 如果给你一周继续优化，你先做什么？
- 答：优先做评估基线和高价值瓶颈（通常是推理吞吐或数据质量）。

46. 若迁移到 1B 参数，优先改哪三件事？
- 答：并行策略、KV 管理、数据规模与质量升级。

47. 如何回答“你是否真的理解项目，而不是照着跑”？
- 答：讲一个你改过的模块和 trade-off，而不是只报命令行。

48. 如何向面试官展示工程思维？
- 答：强调“目标-指标-实验-复盘”闭环。

49. 如果线上用户反馈“答非所问”，你怎么处理？
- 答：收集样本、分类根因、修提示/数据、灰度验证。

50. 一句话定义 minimind 项目经验价值？
- 答：这是把 LLM 从“会用”推进到“能造、能调、能上生产”的关键跳板。
