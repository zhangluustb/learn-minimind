# 06 - Transformer 与 Attention 深度拷问 30 题

## 使用说明

- 每题包含：问题、核心回答、追问点。
- 建议答题节奏：先结论，再公式/机制，再工程影响。

## 30 题清单

### 1. 为什么 Transformer 能替代 RNN？
- 核心回答：自注意力并行度高、长依赖路径短（$O(1)$ 路径），RNN 的长依赖路径是 $O(n)$。
- 追问点：复杂度从时间并行角度看 Transformer 更友好，但在超长序列上 attention 的 $O(n^2)$ 会成为瓶颈。

### 2. Self-Attention 的本质是什么？
- 核心回答：对每个 token 生成 Query，与全序列 Key 做相似度，softmax 后加权 Value，完成“按需读全局上下文”。
- 追问点：为何缩放 $1/\sqrt{d_k}$：避免点积方差过大导致 softmax 饱和。

### 3. 为什么 attention 要 softmax，而不是直接线性归一化？
- 核心回答：softmax 产生概率分布，强调重要位置并抑制噪声，梯度性质更稳定。
- 追问点：替代方案 sparsemax/entmax 可得到稀疏分布，但训练稳定性和生态支持不如 softmax。

### 4. Multi-Head Attention 到底提升了什么？
- 核心回答：不同 head 在不同子空间学习不同依赖关系（语法、指代、位置模式），提升表达能力。
- 追问点：头数过多会出现“冗余头”，需要剪枝或 head importance 分析。

### 5. 为什么 head_dim 常取 64？
- 核心回答：工程上是性能和表达能力折中，且硬件 kernel 对 64 维常有较好优化。
- 追问点：并非必须，核心是 hidden size 可整除并兼顾显存与吞吐。

### 6. 为什么 RoPE 更适合 LLM？
- 核心回答：RoPE 将位置信息编码为旋转，相对位置自然体现在内积里，外推能力优于绝对位置编码。
- 追问点：RoPE 也会在超长上下文衰减，需要 YaRN/NTK scaling。

### 7. ALiBi 和 RoPE 的主要差异？
- 核心回答：ALiBi 通过线性 bias 建模距离惩罚，简单稳健；RoPE 表达更丰富，主流 LLM 使用更广。
- 追问点：ALiBi 不需要复杂旋转计算，长上下文迁移通常更平滑。

### 8. Causal Mask 的作用是什么？
- 核心回答：保证位置 $i$ 只能看到 $\le i$ 的 token，防止训练时“偷看答案”。
- 追问点：训练和推理都需要自回归约束，但推理依赖 KV-Cache 实现高效增量。

### 9. 为什么 attention 的复杂度是 $O(n^2)$？
- 核心回答：每个位置都要和所有位置计算相关性，得到 $n\times n$ 的注意力矩阵。
- 追问点：FlashAttention 优化的是访存而非理论复杂度。

### 10. FlashAttention 的关键收益是什么？
- 核心回答：减少 HBM 读写，把中间结果分块在 SRAM 中计算，显著提速并降显存。
- 追问点：不是“新 attention 公式”，而是 IO-aware kernel 优化。

### 11. Pre-Norm vs Post-Norm 如何选？
- 核心回答：Pre-Norm 更稳定、易训练深层网络；Post-Norm 早期常用但深层易训练不稳。
- 追问点：现代大模型几乎都偏 Pre-Norm。

### 12. RMSNorm 比 LayerNorm 快在哪里？
- 核心回答：RMSNorm 不做均值中心化，仅按均方根缩放，计算更简单、速度更好。
- 追问点：效果通常接近 LayerNorm，工程上更常见。

### 13. 为什么 FFN 参数量通常比 attention 大？
- 核心回答：FFN 常用扩展维度（如 4x hidden），两次线性层带来大量参数。
- 追问点：SwiGLU 会改变中间维配置，通常进一步提升表达能力。

### 14. SwiGLU 相比 ReLU/GELU 的优势？
- 核心回答：门控机制提高非线性表达能力与训练稳定性，许多 LLM 实证更优。
- 追问点：参数和计算开销略增。

### 15. 什么是 GQA？为什么有价值？
- 核心回答：多个 Query head 共享较少的 KV heads，显著降低 KV-Cache 内存。
- 追问点：在保持质量的前提下提升推理吞吐，是大模型部署关键技巧。

### 16. MHA、MQA、GQA 如何取舍？
- 核心回答：MHA 质量最好但缓存大；MQA 缓存最小但可能掉点；GQA 是中间平衡点。
- 追问点：生产环境常优先 GQA。

### 17. Attention Logits 为什么要加数值稳定技巧？
- 核心回答：softmax 前减去 max，避免指数溢出。
- 追问点：混合精度下更关键。

### 18. QK-Norm 是什么，何时有用？
- 核心回答：对 Q、K 做归一化，控制 logits 尺度，提升训练稳定性。
- 追问点：常见于高学习率或较激进配置下。

### 19. 为什么说 Transformer 的“记忆”来自 KV-Cache？
- 核心回答：在推理阶段，模型通过 KV-Cache 保留会话历史上下文表示；这是“会话记忆”，不同于参数中存储的长期知识。
- 追问点：区分三类记忆：参数记忆（训练得到）、上下文记忆（prompt）、缓存记忆（推理态 KV）。

### 20. KV-Cache 为什么能把推理复杂度从“重算全序列”降下来？
- 核心回答：每步只算新 token 的 Q/K/V，历史 K/V 直接复用，避免了“每步重算整段前缀”的额外开销；因此相对无缓存方案显著提速。
- 追问点：在全注意力下，单步对历史 K 的注意仍随上下文长度增长（非严格常量）；KV-Cache 降的是重算成本而不是把复杂度变成 O(1)。

### 21. 位置编码能否放在 Value 上？
- 核心回答：常见做法是作用在 Q/K，直接影响相似度计算；放在 V 上语义不同且效果通常不佳。
- 追问点：RoPE 核心是让注意力分数携带相对位置信号。

### 22. 为什么 embedding 权重常与输出层权重共享？
- 核心回答：weight tying 可减少参数、提升泛化，输入输出词空间一致。
- 追问点：尤其在中小模型中收益明显。

### 23. 温度 temperature 在解码里做了什么？
- 核心回答：对 logits 除以 $T$，$T<1$ 更保守，$T>1$ 更发散。
- 追问点：与 top-k/top-p 配合调控创造性。

### 24. Top-k 与 Top-p 的差别？
- 核心回答：Top-k 固定候选数量；Top-p 固定累计概率阈值，候选数动态。
- 追问点：Top-p 通常更稳健，适应不同分布尖锐度。

### 25. 为什么会出现重复输出？
- 核心回答：概率分布塌缩、训练数据重复模式、解码策略过贪心导致循环。
- 追问点：可用 repetition penalty、n-gram blocking、更好指令数据缓解。

### 26. 长上下文下注意力退化的表现？
- 核心回答：远距离信息利用下降、定位错误、召回失败。
- 追问点：可通过 RoPE scaling、检索增强（RAG）、分块注意力改善。

### 27. 为什么说 attention 可解释性有限？
- 核心回答：注意力权重不等于因果贡献，"attention is not explanation"。
- 追问点：需结合因果干预、归因方法综合判断。

### 28. Transformer 为什么容易出现幻觉？
- 核心回答：本质是概率生成，不是事实检索器；在不确定区域会生成最像真相的文本。
- 追问点：RAG、工具调用和校验机制是核心缓解手段。

### 29. 推理时 batch 增大会发生什么？
- 核心回答：吞吐上升、单请求延迟可能上升；受显存和调度策略约束。
- 追问点：vLLM 的 continuous batching 能显著改善整体效率。

### 30. 如果要面试中总结 Transformer，一句话怎么说？
- 核心回答：Transformer 用自注意力实现全局信息路由，用前馈网络做逐位置非线性计算，通过堆叠形成强大的序列建模能力。
- 追问点：补一句工程版：RoPE+GQA+RMSNorm+FlashAttention 是现代 LLM 的常见高效组合。

## 快速复盘口诀

- 注意力负责“信息路由”，FFN 负责“局部计算”。
- RoPE 解决位置，GQA 解决缓存，FlashAttention 解决 IO。
- 训练看稳定性（Norm/Mask），推理看吞吐（KV-Cache/Batching/Quant）。
