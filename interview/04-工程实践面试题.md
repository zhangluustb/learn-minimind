## 模块 1：分布式训练

### Q1: 什么是 DDP？为什么要用分布式？

**标准答案：**

DDP（Distributed Data Parallel）是 PyTorch 官方的多 GPU 训练方案。

**为什么需要：**
- 单卡 24GB（A100）放不下 64M 模型（需 ~6GB 权重 + 梯度 + 激活，共 18GB）
- 训练 20B token 需 ~2000 小时单卡，用 8 卡可降到 250 小时

**DDP 原理：**
```
每张 GPU 有模型的完整副本
分别处理不同 batch
每个 step 后用 all-reduce 同步梯度平均

GPU 0: batch 0  -->  梯度 g_0
GPU 1: batch 1  -->  梯度 g_1  --->--- 聚合 avg(g_0, g_1, ...)
...
GPU 7: batch 7  -->  梯度 g_7
```

**代码框架：**

```python
from torch.nn.parallel import DistributedDataParallel as DDP
import torch.distributed as dist

# 初始化
dist.init_process_group("nccl")
model = Model(...).cuda()
model = DDP(model)

# 训练循环（和单卡几乎一样）
for batch in loader:
    logits = model(batch)
    loss = criterion(logits, batch.labels)
    loss.backward()
    optimizer.step()
```

**minimind 的启动方式：**

```bash
# 启动脚本
python -m torch.distributed.launch \
    --nproc_per_node=8 \
    train_pretrain.py
```

**追问：**
- "DDP 有什么缺陷？"
  答：(1) 同步成本，如果卡间 bandwidth 低会有 straggler；(2) 显存消耗不变（每卡还是全模型）。

### Q2: 什么是混合精度训练（Automatic Mixed Precision）？

**标准答案：**

AMP 自动混合使用 FP32 和 FP16/BF16，加速同时保证精度。

**为什么有效：**

| 精度 | 范围 | 优点 | 缺点 |
|------|------|------|------|
| FP32 | ±10^38 | 精度高 | 显存用 4 倍，速度慢 |
| BF16 | ±10^38 | 动态范围大 | 精度低于 FP32 |
| FP16 | ±10^4 | 快速 | 容易下溢（underflow） |

**混合精度策略：**
- **前向 & 梯度计算：** BF16（快）
- **权重更新、loss 缩放：** FP32（保精度）

**实现：**

```python
from torch.amp import autocast, GradScaler

scaler = GradScaler()

for batch in loader:
    with autocast(device_type='cuda'):
        # 自动用 BF16/FP16
        logits = model(batch)
        loss = criterion(logits, batch.labels)
    
    # 缩放 loss，防止梯度下溢
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()
```

**效果：**
- 显存减 40%
- 速度快 1.5-2 倍
- 精度影响 < 0.1%

## 模块 2：推理优化

### Q3: 为什么推理速度比训练慢？如何加快？

**标准答案：**

推理的瓶颈不是计算，而是**内存带宽**（memory bandwidth）。

**推理的计算特点：**
```
生成 1 个 token：
  计算量：~100M 操作（512 dim × 2 层 × attention...）
  显存读取：~500MB （整个模型）
  
  计算密度：100M / 500MB = 0.2 FLOP/byte  （太低！）
  
GPU 的内存带宽：2TB/s
GPU 的算力：312 TFLOPS

瓶颈：受限于内存带宽，无法充分利用算力
```

**加快方法：**

1. **KV-Cache**（第 L09 课）：缓存过去的 K/V，避免重复计算，减 90% 显存读取
2. **页式注意力（Paged Attention，vLLM）**：不连续存储 KV，减少显存碎片
3. **算子融合（Flash Attention）**：把多个小操作合成一个大操作，减少 GPU 访存次数
4. **量化**：INT4 权重，显存读取减 75%

**实际数据：**
```
minimind 推理：
  标准：0.5 second/token（单卡 A100）
  + KV-Cache：0.05 second/token（10 倍加速）
  + 量化：0.02 second/token（25 倍加速）
```

### Q4: 什么是 int4 量化？损精度吗？

**标准答案：**

Int4 量化把 FP32 权重压缩到 4-bit 整数，减 87.5% 显存占用。

**量化过程：**

```
原权重 W ∈ [-2.3, 1.8] (FP32)
   ↓ 缩放到 [-127, 127] 范围
   ↓ 四舍五入到整数
量化权重 W_int4 ∈ {-8, -7, ..., 7} (INT4)
   ↓ 推理时反量化
   ↓ 恢复到原范围（但精度降低）
W' ≈ 2.3 / 127 × W_int4
```

**两种量化方式：**

| 方式 | 精度降 | 优点 | 缺点 |
|------|--------|------|------|
| 均匀量化 | 2-3% | 简单快速 | 对异常值敏感 |
| NF4（Normal Float 4bit） | 0.5-1% | 异常值不敏感 | 复杂度高 |

**minimind 的量化脚本：** convert_model.py (应该有)

```python
model = quantize_model(model, bit=4)
# 权重从 128MB (FP32) 减到 16MB (INT4)
# 推理速度快 2-4 倍
```

**追问：**
- "INT4 精度损失那么小，为什么不全部用 INT4？"
  答：embedding 层精度敏感（词义），通常保留 BF16 或 INT8。其他层用 INT4。

## 模块 3：显存优化

### Q5: 显存都花在哪了？如何优化？

**标准答案：**

**显存构成（训练时，单样本，单卡）：**

```
权重参数：    64M × 4 byte = 256MB
权重梯度：    64M × 4 byte = 256MB  
优化器状态：  64M × 8 byte = 512MB  (Adam: m, v)
激活值：      batch_size × seq_len × dim × 4 = ?

总计：~1.2GB + 激活
```

示例（batch=4, seq_len=512）：
```
激活：4 × 512 × 512 × 4 × 8 层 = ~3.35GB
总计：1.2GB + 3.35GB = 4.5GB
```

**优化策略：**

| 方法 | 减少比例 | 难度 |
|------|---------|------|
| 降低 batch_size | 40% | 简单，但训练变慢 |
| 梯度累积（Gradient Accumulation） | 40% | 简单，无损 |
| LoRA (冻结主体，只训低秩) | 70% | 中等，微调场景 |
| 梯度 checkpointing | 30% | 中等，计算换显存 |
| 量化优化器状态 | 50% | 难，需自定义优化器 |

**梯度累积示例：**

```python
# 不加梯度累积：显存需要 4GB × 8 倍 batch = 32GB
# 加梯度累积：显存只需 4GB

accumulation_steps = 8
for i, batch in enumerate(loader):
    logits = model(batch)
    loss = criterion(logits, batch.labels) / accumulation_steps
    loss.backward()  # 梯度累积
    
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

等效于 batch_size = 8 × 4，但显存只用 1 × 4。

### Q7: 为什么要量化？量化前后模型体积和推理速度对比？

**标准答案：**

**量化目的：** 
1. 减小模型体积，便于部署和下载
2. 加速推理，特别是 CPU 推理

**minimind 量化对比：**

```
                FP32     BF16     INT8     INT4
模型体积       256MB    128MB    64MB     32MB
内存占用       270MB    145MB    70MB     45MB（推理）
推理速度*      1.0x     1.1x     2.0x     3.5x
精度损失       0%       0.1%     0.5%     1-2%

* 基准：单卡 A100，batch=1
```

**量化的代价：**
- INT4：最激进，embedding 可能掉点
- INT8：平衡，无明显掉点
- BF16：只是去掉了 FP32 的冗余精度，基本无损

### Q8: 实现一个简单的批量推理函数，支持动态 batch

**给定：**
- 模型、tokenizer
- 多个 prompt 列表，长度不同
- 需要限制最大显存 2GB

**期望思路：**

```python
def batch_generate(model, tokenizer, prompts, max_memory_mb=2000):
    """
    根据显存限制动态调整 batch_size
    """
    results = []
    batch_size = 32
    
    while batch_size > 0:
        try:
            # 估算显存
            estimated_memory = estimate_kv_cache(
                max_len=512,
                batch_size=batch_size,
                model_dim=512,
                n_layers=8
            )
            
            if estimated_memory > max_memory_mb:
                batch_size //= 2
                continue
            
            # 分批推理
            for i in range(0, len(prompts), batch_size):
                batch_prompts = prompts[i:i+batch_size]
                batch_results = model.generate_batch(batch_prompts)
                results.extend(batch_results)
            
            break
        except RuntimeError as e:
            if "CUDA out of memory" in str(e):
                batch_size //= 2
            else:
                raise
    
    return results
```

**考察点：**
- 动态显存估算
- 错误恢复（OOM 时 fallback）
- 实用的工程思维

**常见异常：**
- Loss = NaN/Inf：学习率太高
- Loss 不动：学习率太低

- 梯度消失（范数 < 1e-4）：检查 batch norm, layer norm 配置
