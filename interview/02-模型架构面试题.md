# 02 - 模型架构面试题

## 模块 1：Transformer 基础

### Q1: 什么是 Self-Attention？为什么叫 "Self"？

**标准答案：**

Self-Attention 是 Transformer 的核心机制。"Self" 的意思是 query、key、value 都来自**同一个输入序列**。

数学形式：
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

其中 query、key、value 都是输入做线性变换得到的。

对比其他注意力机制：
- Cross-Attention：Q 来自一个序列，K/V 来自另一个序列（Seq2Seq 场景）
- Self-Attention：Q/K/V 都来自同一序列（LLM 场景）

**minimind 中的实现：**

```python
class Attention(nn.Module):
    def forward(self, x):  # x shape: [B, T, dim]
        # Attention 中的 Q/K/V 都来自同一个 x
        Q = self.q_proj(x)  # [B, T, dim]
        K = self.k_proj(x)  # [B, T, dim]
        V = self.v_proj(x)  # [B, T, dim]
        
        # 计算 attention weights
        scores = Q @ K.T  # [B, T, T]
        attention_weights = softmax(scores)
        
        # 得到输出（仍是 [B, T, dim]，维度保持不变）
        output = attention_weights @ V
        return output
```

**追问方向：**
- "如果 attention 对角化（每个位置只和自己注意），会发生什么？"
  答：就变成了逐位置的线性变换，完全失去了位置间的交互。Attention 的核心价值就在于能让位置 i 关注位置 j。

### Q2: Multi-Head Attention 的优势是什么？

**标准答案：**

MHA 把单个 attention head 扩展到多个，每个 head 学不同的"注意力模式"。

单头 vs 多头的对比：

| 特性 | 单头 | 多头 |
|------|------|------|
| 参数 | dim² | n_heads × (dim/n_heads)² = dim² |
| 表达能力 | 单一注意力模式 | 多种注意力模式（并行） |
| 示例 | 只能学"临近词注意" | 能同时学"临近词" + "主语-谓语" + "时态协议" |

公式：
$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_n)W^O$$

其中 $\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$

**在 minimind 中：** 

n_heads = 8（8 个 attention head），每个 head 维度 = 512 / 8 = 64

**追问：**
- "为什么是 8 个 head？能用 16 个或 4 个吗？"
  答：经验上 8-16 比较常见。更多 head 表达能力更强但参数数相同，所以理论上可行。但实际中 head 数通常跟 hidden_size 的因子有关（512 = 8×64）。

## 模块 2：minimind 的架构创新

### Q3: 为什么用 GQA 而不是标准 MHA？

**标准答案：**

GQA（Group Query Attention）是一个聪明的设计，核心动机是**减少 KV-Cache 的显存占用**，同时保持相近的效果。

**标准 MHA vs GQA 对比：**

```
MHA: 8 个 Q head，8 个 K head，8 个 V head
     ├─ Q_1 注意 K_1/V_1
     ├─ Q_2 注意 K_2/V_2
     └─ ...（8 对独立的注意）

GQA：8 个 Q head，2 个共享的 K head，2 个共享的 V head
     ├─ Q_1, Q_2, Q_3, Q_4 共享 K_1/V_1
     └─ Q_5, Q_6, Q_7, Q_8 共享 K_2/V_2
```

**KV-Cache 的节省：**
- MHA：缓存 8 对 K/V
- GQA：缓存 2 对 K/V
- 节省比例：75%

**minimind 的配置：**
```python
config = MiniMindConfig(
    n_heads = 8          # Q 头数
    n_kv_heads = 4       # KV 头数（4 < 8）
)
# 结果：KV-Cache 减 50%，参数数不变
```

**效果对比：**
- 性能损失：1-2%（在下游任务上）
- 显存节省：50%
- 推理速度：快 1.2-1.5 倍（内存带宽瓶颈缓解）

**追问：**
- "能降到 1 个 KV head 吗？"
  答：理论可以（MQA），但会掉点比较明显（3-5%）。GQA 是 MHA 和 MQA 的平衡。

### Q4: RoPE 位置编码的原理是什么？

**标准答案：**

RoPE（Rotary Position Embedding）把位置编码变成一个旋转操作，优雅地保证了**只和相对位置有关**。

**数学核心：**

定义旋转矩阵（复数乘法形式）：
$$\mathbf{q}_m \leftarrow R_m \mathbf{q}_0, \quad \mathbf{k}_n \leftarrow R_n \mathbf{k}_0$$

其中 $R_\theta$ 是旋转矩阵。关键性质：
$$\mathbf{q}_m^T \mathbf{k}_n = \mathbf{q}_0^T R_{n-m} \mathbf{k}_0$$

**只和 $m - n$（相对位置）有关！**

这比绝对位置编码聪明得多：
- 绝对编码：必须在训练数据中见过的长度
- RoPE：天然支持外推到任意长度（因为只关心相对位置的"旋转角度"）

**在 minimind 中的实现：**

```python
def precompute_freqs_cis(dim, end, theta=10000.0):
    """预计算旋转频率 (cos, sin)"""
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2) / dim))
    t = torch.arange(end)
    freqs = torch.outer(t, freqs)
    return torch.cos(freqs), torch.sin(freqs)

def apply_rotary_emb(xq, xk, freqs_cos, freqs_sin):
    """用复数乘法施加旋转"""
    # 最后维度分成两对，进行复数旋转
    xq_r, xq_i = xq[..., :dim//2], xq[..., dim//2:]
    xk_r, xk_i = xk[..., :dim//2], xk[..., dim//2:]
    
    # 复数乘法：(a+bi)(cos+isin) = (a·cos-b·sin) + i(a·sin+b·cos)
    xq_out_r = xq_r * freqs_cos - xq_i * freqs_sin
    xq_out_i = xq_r * freqs_sin + xq_i * freqs_cos
    ...
```

**YaRN 优化：** 长文本外推时，不同频率的维度用不同的缩放策略，支持 4-8 倍的长度外推而不需重训。

## 模块 3：深度追问

### Q5: FFN 和 Attention 各自的作用是什么？

**标准答案：**

Transformer Block 中 Attention 和 FFN 分工不同：

| 维度 | Attention | FFN |
|------|-----------|-----|
| 作用 | **Mixing**：让不同位置的信息交融 | **Reasoning**：对单位置特征的非线性变换 |
| 输入依赖 | 看整个序列 | 只看当前位置 |
| 参数量 | ≈ dim² × n_heads | ≈ dim × 4dim × 2 = 8dim² |
| 比例 | 总参数的 ~35% | 总参数的 ~65% |

即：**Attention 负责"通讯"，FFN 负责"计算"。**

**追问 1：** "为什么 FFN 的参数比 Attention 多得多？"

答：FFN 用"放大-激活-收缩"的结构做非线性变换。放大到 4dim（或用 SwiGLU 时 8dim/3），这是必要的非线性编码。

**追问 2：** "如果去掉 Attention，只用 FFN，会怎样？"

答：模型退化为独立处理每个位置，完全失去了位置间的依赖。无法理解需要全局信息的任务（如代词指代、长依赖等）。

### Q6: QK-Norm 是什么？为什么需要？

**标准答案：**

QK-Norm 对 query 和 key 矩阵进行 L2 归一化，稳定 attention 计算。

**问题：** 当 Q/K 没有归一化时，它们的范数可能很大（如 10-100），导致：
- $QK^T$ 的值太大
- softmax 会产生接近 one-hot 的极端分布
- 梯度消失或爆炸

**解决：** 把 Q 和 K 各自归一化到单位长度，再计算 attention：
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{\text{norm}(Q) \cdot \text{norm}(K)^T}{\sqrt{d_k}}\right)V$$

**效果：**
- 训练稳定性 提升 40%
- Loss 收敛速度 快 1.3-1.5 倍
- 允许更大的学习率

**minimind 支持：** 

```python
if config.qk_norm:
    Q = F.normalize(Q, dim=-1)
    K = F.normalize(K, dim=-1)
```

## 模块 4：设计题

### Q7: 如果要把 minimind 从 64M 扩展到 1B，架构上需要改什么？

**期望的分析纬度：**

1. **KV-Cache：** 显存会激增，可能需要 Paged Attention（vLLM 方案）
2. **MoE：** 1B 参数用 Dense FFN 过度，需要考虑 MoE
3. **量化：** INT4 可能不够，要用 NF4 或保留 BF16
4. **分布式：** 单卡放不下，需要 DDP/Tensor Parallel
5. **数据：** 更多高质量数据，避免过拟合

## 模块 5：coding 题

### Q8: 如何实现 repeat_kv 函数（GQA 的关键）？

**给定：** 
- KV shape：`[B, T, n_kv_heads, head_dim]`
- 需要扩展到：`[B, T, n_heads, head_dim]`

**实现：**

```python
def repeat_kv(x, n_rep):
    """
    x: [B, T, n_kv_heads, head_dim]
    n_rep: n_heads // n_kv_heads（如 8 // 4 = 2）
    """
    if n_rep == 1:
        return x
    bs, slen, n_kv_heads, head_dim = x.shape
    # 方案 1：简单但低效（涉及多次 reshape）
    return x[:, :, :, None, :].expand(
        bs, slen, n_kv_heads, n_rep, head_dim
    ).reshape(bs, slen, n_kv_heads * n_rep, head_dim)
```

**考察点：**
- 是否理解 GQA 的扩展机制
- Tensor 操作的熟练度（expand vs tile vs repeat）
- 内存高效性考虑
