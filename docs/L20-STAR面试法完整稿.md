### 1. STAR 法则深层结构

**S（Situation）—— 背景设定**

目的：让面试官理解你遇到的真实问题，而非假设题。

✅ 好的 Situation：
- "当时 minimind 的预训练损失一直在 3.5 卡住，怎么都下不来…"
- "我注意到用 Full SFT 时显存不够，无法在单卡 3090 上运行…"

❌ 差的 Situation：
- "我学了 Transformer"
- "我想优化一个模型"

**T（Task）—— 目标明确**

你在这个场景中要解决什么具体问题。

✅ "我的任务是在 3 小时内用 ¥3 的成本完成从零到有可用模型的全链路"

❌ "学习 LLM"

**A（Action）—— 行动具体**

这是最容易被问"追问"的部分。一定要说出：
- 尝试了什么方案
- 为什么这样选
- 遇到了什么坑
- 怎么解决的

✅ "我先用 Adam 优化器，但 loss 震荡，后来改成 AdamW + Warm-up，loss 才平稳下降…"

❌ "用 PyTorch 训练"

**R（Result）—— 量化结果**

没有量化的结果就没有说服力。

✅ "最终 3 元成本、2 小时训练，模型在下游任务上达到 85% 的精准度"

❌ "模型训练完了"

### 3. 核心难点 STAR 深度稿（7 个核心题）

#### 难点 1：RoPE 位置编码为什么比绝对位置编码更好

```
【Q】为什么放弃 Transformer 原始的绝对位置编码，改用 RoPE？

【S】当时我在读论文时发现，官方 Transformer 的位置编码有个问题：
- 绝对位置编码只能泛化到训练时见过的位置长度
- 比如训练时最长 512 token，推理时遇到 1024 token 就瞎了

【T】我需要理解：应该选绝对编码、学习型编码，还是相对编码？

【A】我逐个对比：
1. 绝对编码（sin-cos）：简单但无法外推 ❌
2. 学习型编码（BERT）：可以训练但低效 ⚠️
3. RoPE：把位置编码变成旋转，相对位置 = 两个角度的差
   - 数学上：$\mathbf{q}_m^T \mathbf{k}_n$ 只依赖于 $m - n$（相对位置）
   - 实现上：用复数乘法代替矩阵乘法，是一个优雅的技巧

我还看了 YaRN 论文，发现 RoPE 的进一步优化：不同频率维度可以用不同缩放策略，支持长文本外推而无需重新训练。

【R】最终在 minimind 中选了 RoPE：
- ✅ 天然支持长文本外推（用了 YaRN）
- ✅ 相对位置的表达更符合语言模型的直觉
- ✅ 复数乘法快于矩阵乘法，推理更高效
- 有人问能不能用绝对编码，我会说这里是设计选择，需要权衡

【追问准备】
Q: "RoPE 在很长的序列上表现如何？"
A: "即使不用 YaRN，RoPE 也能外推到 2-3 倍的序列长度。但要支持 10 倍外推，YaRN 的频率缩放是必要的。我在 minimind 中实现了这个，模型在 4096 长度上表现良好。"
```

#### 难点 2：DPO vs RLHF，为什么能绕过奖励模型

```
【Q】DPO 相比 RLHF+RM 的核心优势是什么？可以完全替代吗？

【S】RLHF 是业界标准，但有个痛点：需要训练一个中间的奖励模型，增加了复杂性和成本。

【T】我想理解 DPO 如何在不显式训练 RM 的情况下达到 RLHF 的效果。

【A】数学推导（我在论文中看到并在 minimind 中实现了）：
1. 出发点：Bradley-Terry 模型定义了偏好和奖励的关系
   $$P(y_1 \succ y_2) = \sigma(\text{RM}(y_1) - \text{RM}(y_2))$$

2. 通过变量替换，证明了最优策略满足一个约束

3. 反推：如果我们给定偏好对 $(y_1 \text{ 比 } y_2 \text{ 更好})$，可以直接优化来让模型的行为满足这个约束，**无需显式 RM**

4. 最终 loss：
$$L_{\text{DPO}} = -\log \sigma\left(\beta (\log \frac{\pi_\theta(y_1 | x)}{\pi_{\text{ref}}(y_1 | x)} - \log \frac{\pi_\theta(y_2 | x)}{\pi_{\text{ref}}(y_2 | x)})\right)$$

【R】我在 minimind 中实现了 DPO 并与 RLHF 对比：
- 计算：DPO 不需要奖励模型额外推理，快 30-50%
- 工程简洁性：RLHF 需要 actor/critic/rm 三个模型，DPO 只需要两个（training 和 reference）
- 效果：DPO 在我的测试中与 RLHF 相当，某些任务上更稳定

限制：DPO 假设偏好对是正确的。如果标注数据有噪声，RLHF 的奖励模型可以学到某种鲁棒性。

【追问准备】
Q: "DPO 在大规模生产环境中应该怎么用？"
A: "我认为可以结合：用小数据集做 DPO 快速迭代，满意后用奖励模型做 RLHF 精调。两者互补。"
```

#### 难点 3：LoRA 为什么有效

```
【Q】LoRA 能用 1% 的参数达到接近全参数 SFT 的效果，这背后的直觉是什么？

【S】全参数 SFT 需要大量显存，LoRA 让小团队也能微调大模型。

【T】理解为什么低秩更新 $\Delta W = BA$ 能代表大部分的学习。

【A】几个角度的理解：
1. 【数据角度】SFT 数据相比预训练数据少 1000-10000 倍，权重更新的自由度本来就不需那么高
   - 预训练学"广泛的世界知识"，需要满秩
   - SFT 只是微调"说话风格"，可能只在一个小的子空间里变化

2. 【数学角度】假设最优的权重更新 $\Delta W$ 是满秩的，但通过 SVD 分解，99% 的能量集中在前 $ r $ 个奇异向量
   - 保留 r=64 的秩足以捕捉这 99% 的信息量

3. 【工程角度】LoRA 不止是参数节省，还有正则化效果
   - 限制了参数更新的"复杂度"
   - 某些任务上精度反而更高，因为避免了过拟合

4. 【实现细节】初始化很关键：
   - $B = 0$（从零开始，确保 $\Delta W$ 一开始是 0）
   - $A$ 随机初始化
   - 这样 frozen 的 $W$ 不会在一开始就被破坏

【R】minimind 中用 LoRA 训练 SFT：
- 参数数从 64M → 8M（保留了 Attention 和 FFN 的投影）
- 显存从 1GB → 200MB（4 倍节省）
- 效果：与全参数 SFT 性能差 2-3%，但训练快 5 倍

【追问准备】
Q: "能说一下 LoRA 的秩应该怎么选吗？"
A: "实验中我发现 r=8-64 是最优范围。太小（r<8）性能掉得明显，太大（r>128）就没有参数节省的意义了。最好的办法是在验证集上试几个值。"
```

#### 难点 4-7：简化回答

由于篇幅限制，难点 4-7 的简化版本：

**难点 4：GQA 相比 MHA**
- 降低 KV-Cache 显存 75%
- 保留 95-98% 效果
- 权衡：参数稍多，但推理省显存得不偿失的 case 少

**难点 5：SFT 中的 Loss Masking**
- 只计算答案部分，不算指令部分
- 防止模型"记住"标准问法，真正理解语义

**难点 6：混合精度训练**
- BF16 计算，FP32 维护梯度和优化器状态
- 显存 1/2，速度 2 倍

**难点 7：KV-Cache 的具体管理**
- 每一步追加新 token 的 K/V，无需重算历史
- 内存线性于序列长度，推理时间也线性

### 4. 模拟 12 轮真实面试

#### 第 1-3 轮：技术基础（Warm-up）

**Q1: "请用 3 分钟自我介绍"**
→ 用上面准备的 3 分钟稿

**Q2: "minimind 和 LLaMA 最大的区别是什么？"**
A: "参数量（64M vs 7B）和目标不同。LLaMA 是生产级，minimind 是教学级。更重要的是，minimind 的每个选择（GQA、RoPE、SwiGLU、DPO）都是为了展示'为什么这样设计'。"

**Q3: "为什么选择这样的模型大小（64M）？"**
A: "64M 在单卡 3090 上可以完整训练、推理、微调，成本约 3 元。这是一个甜蜜点——足够小到任何人都能实验，足够大到展示真实 LLM 的所有技术。"

#### 第 4-6 轮：核心技术深问

**Q4: "从预训练的 loss 曲线，怎么看出模型在学到有意义的东西？"**
A: "主要看几个指标：
1. Loss 是否平稳下降（不震荡）
2. 最终 loss 是否接近理论下界（约 2-3 bits of entropy）
3. 生成的文本是否从"乱码"逐渐变成"连贯的句子"
在 minimind 中，我追踪了所有 training 过程，并用 tensorboard 可视化。"

**Q5: "为什么 DPO 能比 PPO 更高效且不需要奖励模型？"**
→ 用上面的"难点 2"深度稿

**Q6: "如果要在生产环境部署 minimind，你会怎么做？"**
A: "三步：
1. 量化：INT4 压缩到 32MB（支持 CPU）
2. 框架选型：用 vLLM 支持批量请求（吞吐 4-8x）
3. API 暴露：OpenAI 兼容接口，方便前端对接
我在 minimind 中都实现了这些，可以现场演示。"

#### 第 7-9 轮：工程挑战

**Q7: "训练过程中遇到过什么最困难的问题？"**
A: "最大的问题是初期的 loss 不下降。我排查了 3 天，最后发现是数据处理的 bug——token 序列没有正确对齐。修复后 loss 立刻下降。这让我意识到数据流的重要性。"

**Q8: "KV-Cache 的管理有什么坑？"**
A: "两个主要的坑：
1. Position ID 的维护——decode 时 position 要递增，不能总是 0
2. Batch 处理——不同请求的 KV 长度可能不同，简单的 cat 会导致 shape 错位
我在代码中用了很多 assert 来抓这些 bug。"

**Q9: "怎么衡量 SFT 阶段是否过拟合？"**
A: "用训练集和验证集的 loss gap：
- Gap < 0.1：没有过拟合
- Gap 0.1-0.5：轻微过拟合，可控
- Gap > 0.5：严重过拟合
我的方案是混合 90% 预训练数据 + 10% SFT 数据，这样即使 SFT 时长，也不会遗忘预训练知识。"

#### 第 10-12 轮：开放性与反问

**Q10: "这个项目中最创新的地方是什么？"**
A: "不是单项技术的创新，因为都是论文里的方法。创新在于整合：
- 选用最新论文的技术（RoPE、GQA、DPO）
- 首次在如此小的模型上完整验证 RLHF 全流程
- 用教学的角度重写了代码和文档
这种"整合创新"在工业实践中同样重要。"

**Q11: "如果要扩展 minimind 到 1B 参数，最大的瓶颈是什么？"**
A: "两个：
1. 显存：1B 的 KV-Cache 会吃满一张 80GB 的 A100。需要 Paged Attention 或分布式推理
2. 数据：1B 需要更多高质量的 SFT/RLHF 数据。64M 可以用公开数据集自嗨，1B 的应用性会遇到瓶颈
我认为这也是为什么业界的"最小有用的生产模型"是 7B。"

**Q12: "有什么想问我们公司的？"**
A: "我想了解：
1. 贵公司在 LLM 方面最关注的是推理效率、成本、还是创新能力？
2. 现在在用什么框架和优化方案？我很好奇在实际生产中推理和训练的权衡怎么做。
3. 如果招我的话，前三个月会做什么项目？"
